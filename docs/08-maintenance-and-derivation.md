# Maintenance and Derivation Workers

## 1. Core principle

Mind Place does not require an internal AI system to store memory.

However, external AI coding and agent tools may be extremely useful for maintenance and derivation.

Potential workers include:

- Codex;
- Claude Code;
- Antigravity;
- Cowork-style agents;
- future local or hosted agents.

These workers operate above the canonical source layer.

## 2. What a worker may do

Examples:

- cluster conversations by project;
- infer topic labels;
- propose graph edges;
- generate conversation summaries;
- build project timelines;
- identify duplicate curated memories;
- extract entities;
- generate a project context pack;
- detect stale derived data;
- rebuild embeddings;
- reorganize derived indexes.

## 3. What a worker must not do silently

A worker should not:

- rewrite original conversations;
- modify original file bytes;
- fabricate source provenance;
- delete raw history merely because a summary exists;
- convert an inference into canonical user truth without labeling it;
- overwrite manual graph edits without explicit policy.

## 4. Raw versus derived lifecycle

~~~text
RAW SOURCE
   |
   +----------------------+
   |                      |
worker A               worker B
   |                      |
summary               graph edges
   |                      |
   +----------+-----------+
              |
         DERIVED LAYER
~~~

If a better model appears:

~~~text
delete derived output
      |
run better worker
      |
rebuild
~~~

The source remains unchanged.

This is especially valuable in an environment where frontier models improve rapidly.

## 5. Chaining

The brainstorming includes a chaining idea: memories and sources can be progressively connected into a hive-like graph.

A safe pipeline could be:

~~~text
new raw data
    |
deterministic indexing
    |
candidate entity and topic extraction
    |
candidate relationships
    |
deduplication and reconciliation
    |
graph update as DERIVED edges
~~~

Automatic edges should retain:

- origin;
- model or tool version;
- timestamp;
- confidence if applicable;
- supporting sources.

## 6. Background processing should be optional

The local archive should remain fully usable when:

- the machine is offline;
- no API key is configured;
- no coding agent is installed;
- monthly AI budget is zero.

Core functionality still includes:

- capture;
- browsing;
- lexical search;
- manual memories;
- manual graph editing;
- MCP retrieval.

## 7. Scheduling options

Workers may eventually run:

- manually;
- after a number of new conversations;
- while the machine is idle;
- per project;
- on demand before research;
- during an explicit rebuild operation.

Avoid continuous expensive inference by default.

## 8. Maintenance profiles

### Minimal

- deterministic index only;
- no AI processing.

### Assisted

- user manually runs an external model to reorganize selected data.

### Automatic

- configured worker periodically derives graph and summaries.

These should share the same underlying data model.

## 9. Worker input boundaries

A worker should receive scoped material, not necessarily the entire archive.

Example:

~~~text
task: reconcile one project graph
sources:
  - conversations tagged with project
  - current project graph
  - project curated memories
token budget: bounded
~~~

This reuses the same retrieval engine used by chat models.

## 10. Worker output should be structured

Instead of letting a coding agent rewrite database files directly, prefer operations such as:

~~~json
{
  "operations": [
    {
      "type": "upsert_edge",
      "from": "...",
      "to": "...",
      "relation": "related_to",
      "evidence": ["..."]
    }
  ]
}
~~~

The core validates and commits operations.

This creates a clean trust boundary.

## 11. Reproducibility metadata

Derived artifacts should optionally record:

- worker or provider;
- model;
- prompt or pipeline version;
- code version;
- timestamp;
- source set or hash.

This is useful when comparing a new generation of derived data against old output.

## 12. Why this architecture ages well

Model competition is expected to continue.

A maintenance process generated by today's best model should not become permanent infrastructure.

By keeping raw data stable and derivation replaceable, Mind Place benefits from future models without requiring migration of historical truth.
